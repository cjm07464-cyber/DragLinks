### 이유

- 플레이어블 캐릭터, 유니크, 스테이지 등 장기 확장을 고려.

## 2026-08-25 — 보석/망치 주체 확정

### 결정
- 숫자 타일 → 보석 속성
- 연산자 타일 → 망치 속성

### 일반 보석 폭발
일반 수식 능력으로 보석이 터질 때 3×3:
- 숫자 → 보석
- 연산자 → 망치
- 현재 수식 경로 타일은 주변 변환 대상에서 제외

### 과거안
과거에는 보석/망치의 주체가 반대였으나 폐기되었다.

## 2026-08-25 — LINKING 판정 확정

### 결정
가로 또는 세로 **한 줄 전체가 Number 타일**이면 LINKING이다.

- 현재 숫자값 무관
- NumberIdentity 무관
- 색 무관
- 대각선 LINKING 없음

가로/세로가 교차하면:
- 라인 수는 각각 카운트
- 실제 제거 타일은 합집합으로 한 번만 제거

## 2026-08-25 — LINKING 제거는 연산/사용 판정

### 결정
LINKING으로 실제 제거되는 숫자 타일은:
- 연산 O
- 사용 O
- 파괴 X

따라서 유니크1 같은 "숫자 1 고유 속성을 N회 사용" 조건에 LINKING으로 제거된 숫자 1도 포함된다.

## 2026-08-25 — 연쇄 콤보를 지속형 스택으로 변경

### 폐기된 과거안
- 한 번의 LINKING 해결에서 총 라인 수를 계산
- 턴마다 임시 스택 생성
- 최종 스택 효과 1회만 발동
- 턴 종료 시 스택 소멸

### 최신 결정
- 한가은의 연쇄 콤보 현재 스택은 턴을 넘어 유지한다.
- 현재 스택은 0에서 시작한다.
- LINKING 라인 하나는 "콤보 정산 대기 횟수" 1개를 만든다.
- 현재 보드의 LINKING을 먼저 모두 해결한다.
- LINKING이 더 이상 없으면 대기 횟수를 하나씩 소비한다.
- 횟수 1개 소비마다 현재 스택 +1 후 해당 단계 효과를 실행한다.
- 5스택 효과 발동 후 현재 스택은 0으로 초기화된다.
- 남은 대기 횟수는 사라지지 않고 0스택부터 계속 정산한다.

예:
- 시작 스택 4
- 이번 보드에서 LINKING 2줄
- 첫 정산: 4→5, 5스택 발동 후 0
- 두 번째 정산: 0→1, 1스택 발동
- 최종 유지 스택 1

## 2026-08-25 — 한가은 최신 연쇄 콤보 효과 확정

### 1스택
보석이 아닌 숫자 타일 중 무작위 최대 2개에 보석 부여.

### 2스택
보석이 아닌 숫자 타일 중 무작위 최대 5개에 보석 부여.

### 3스택
보석이 아닌 숫자 타일 중 무작위 최대 7개에 보석 부여.

### 4스택
현재 보드 보석 숫자 타일 수를 `n`으로 계산하고, 현재 모든 보석 숫자 타일의 현재 숫자값을 각각 `+n`.

### 5스택
1. 보석이 아닌 숫자 타일 중 무작위 최대 11개에 보석 부여
2. 파괴 대상인 모든 보석 숫자 타일의 현재 숫자값 합 `S` 저장
3. 모든 보석 숫자 타일을 실제 파괴
4. 스택 0
5. Gravity / Refill
6. 새 LINKING이 있으면 모두 해결
7. 추가 LINKING 라인 수를 콤보 정산 대기 횟수에 추가
8. LINKING이 완전히 끝나면 현재 보드의 모든 숫자 타일 현재값을 각각 `+S`
9. 이후 남아 있던 콤보 정산 대기 횟수 처리를 재개

## 2026-08-25 — 5스택 보석 제거는 실제 파괴

### 결정
5스택에서 제거되는 보석 숫자는:
- 연산 X
- 사용 X
- 파괴 O

따라서:
- 유니크1 사용 횟수에 포함되지 않는다.
- 타일 자체가 보드에서 제거된다.
- 빈칸이 생기므로 Gravity / Refill이 발생한다.

이 규칙은 과거의 "보석 속성만 제거" 안을 대체한다.

## 2026-08-25 — 4/5스택 상승변화 기준

### 4스택
`n = 현재 보드 보석 숫자 타일 개수`

보석 숫자 타일 각각:
`CurrentValue += n`

### 5스택
`S = 5스택에서 실제 파괴되는 모든 보석 숫자 타일의 파괴 직전 CurrentValue 합`

5스택 파괴/Refill/LINKING 후 최종 보드의 모든 숫자 타일:
`CurrentValue += S`

둘 다 고유 숫자 속성은 변경하지 않는다.

## 2026-08-25 — 한가은 수식 Gem/Hammer 주변 효과 변경

### 폐기
보석 주변 Number에 숫자값 `+1`을 직접 주는 방식은 사용하지 않는다.

### 최신 결정
Hammer + Gem 수식 능력 발동 시 Gem의 3×3 주변을 조사한다.

- 주변 Number 1개 발견 → 현재 보드의 Number 중 랜덤 1개에 Gem 부여 시도 1회
- 주변 Number가 여러 개면 그 수만큼 전역 Gem 부여 시도
- 주변 Operator → 해당 Operator 자체에 Hammer 부여
- 새로 생성된 Gem/Hammer가 즉시 재발동하지 않음

세부 랜덤 후보 정책(기존 Gem 제외 여부, 현재 수식 경로 제외 여부)은 구현 전 문서의 상태 태그를 확인한다.
