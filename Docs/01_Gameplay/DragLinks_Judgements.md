# Drag Links! — Gameplay Judgements

> 문서 버전: 0.1  
> 기준일: 2026-08-25  
> 목적: 유니크/캐릭터/스테이지 효과가 참조할 **연산, 사용, 파괴, 변화** 판정을 한곳에 정의한다.

## 1. 왜 분리하는가

Drag Links!에서는 타일이 보드에서 사라졌다고 해서 모두 같은 이유로 사라진 것이 아니다.

예:
- 수식에 넣어 사용
- LINKING으로 자동 사용
- 캐릭터 능력으로 강제 파괴

이 차이는 유니크 조건과 캐릭터 능력에 직접 영향을 준다.

따라서 제거 애니메이션 하나만 보고 판정을 추론하지 않는다.

## 2. 연산 판정

**연산**은 게임 규칙상 타일이 수식/보드 연산 처리에 참여했다는 판정이다.

현재 확정 사례:
- 정상 수식에 포함된 숫자 타일
- LINKING으로 제거되는 숫자 타일

현재 확정 제외:
- 한가은 5스택으로 강제 파괴되는 보석 숫자 타일

LINKING은 실제 산술식이 아니어도 게임 내부 판정상 **연산**으로 취급한다.

## 3. 사용 판정

**사용**은 플레이어/게임 연산 처리로 해당 타일을 실제 소비했다는 판정이다.

현재 확정:
- 정상 수식에 사용된 숫자 → 사용
- LINKING으로 실제 제거된 숫자 → 사용

현재 확정 제외:
- 한가은 5스택 파괴 → 사용 아님

유니크1의 "숫자 1 고유 속성을 5번 사용"은 이 판정을 참조한다.

## 4. 파괴 판정

**파괴**는 연산/사용과 별개로 타일을 강제로 제거하는 판정이다.

현재 확정 사례:
- 한가은 5스택의 모든 보석 숫자 실제 제거

5스택 파괴 타일:
- 연산 X
- 사용 X
- 파괴 O

파괴된 숫자 1 고유 속성 타일은 유니크1 사용 횟수에 포함되지 않는다.

## 5. 변화 판정

숫자 타일의 현재값 또는 고유 속성/상태가 바뀌는 효과는 변화 판정으로 구분할 수 있다.

### 상승변화
현재 숫자값이 증가.

현재 예:
- 유니크1 `+10`
- 한가은 4스택 `+n`
- 한가은 5스택 최종 `+S`

이 변화들은 **현재 숫자값만 변경**하며 고유 숫자 속성은 유지한다.

### 고유 속성 변화
현재 기획상 유니크9가 예외적으로 NumberIdentity/색을 변경한다.

## 6. 현재 판정 표

| 원인 | 연산 | 사용 | 파괴 | 상승변화 |
|---|:---:|:---:|:---:|:---:|
| 수식에 포함된 숫자 제거 | O | O | X | X |
| LINKING으로 실제 제거된 숫자 | O | O | X | X |
| 한가은 4스택의 보석 숫자 +n | X | X | X | O |
| 한가은 5스택 보석 숫자 실제 제거 | X | X | O | X |
| 한가은 5스택 후 현재 숫자 전체 +S | X | X | X | O |
| 유니크1 숫자 1 계열 +10 | X | X | X | O |

## 7. 교차 LINKING

가로/세로 LINKING이 교차하면:
- LineCount는 각각 센다.
- 교차 타일은 실제로 한 번만 제거한다.

[현재안] 사용 판정 또한 실제 제거되는 타일 기준으로 한 번만 기록한다.

이 항목은 유니크 카운트 구현 전 필요하면 최종 확인한다.

## 8. 구현 권장

타일 제거 자체와 판정 이벤트를 결합하지 않는다.

권장 개념 예:
- `TileRemovalReason`
- `GameplayJudgement`
- `TileUsedEvent`
- `TileDestroyedEvent`
- `NumberValueChangedEvent`

정확한 클래스/enum 이름은 현재 코드 구조에 맞게 조정한다.

중요:
- View/Animation이 판정 이벤트를 만들지 않는다.
- Logic에서 판정을 확정하고 View는 결과를 표현한다.
- 하나의 제거에 해당하는 판정을 명시적으로 함께 기록한다.
